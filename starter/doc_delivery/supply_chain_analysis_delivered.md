**Remediation for the fixable HIGH findings:**
- Upgrade `wheel` to **≥ 0.46.2** and `jaraco.context` to **≥ 6.1.0** in the
  build environment and pin them in `requirements.txt`.

  ride in via the Debian base image. Rebuild on the latest patched base image
  on a schedule, and strip `linux-libc-dev` from the final image if nothing at
  runtime needs kernel headers (they are a build-time dependency only).

## Dockerfile Issues

The analyzer found **6** issues in the `Dockerfile`.

### 1. Container runs as root (no USER directive) — HIGH
**Risk:** There is no `USER` instruction, so the Flask RAG service runs as
UID 0. If the app is compromised (e.g. through the injection/exfiltration paths
found in Phase 3), the attacker already has root inside the container, making
container escape and lateral movement far easier.
**Fix:** `RUN useradd -m appuser` and add `USER appuser` before `CMD`.

### 2. Base image not pinned to a digest — MEDIUM
**Risk:** `FROM python:3.11-slim` uses a mutable tag. The bytes behind that tag
can change between builds, so builds are not reproducible and a poisoned
upstream image could be pulled silently.
**Fix:** Pin by digest — `FROM python:3.11-slim@sha256:<digest>`.

### 3. `COPY . /app` copies the entire build context — MEDIUM
**Risk:** The whole repo is baked into the image. Without a strict
`.dockerignore`, this can include `.env` (the OpenAI/Vocareum key), `.git`
history, model checkpoints (`*.pt`), and datasets.
**Fix:** Copy only what runtime needs and add a `.dockerignore` excluding
`.env`, `.git`, `__pycache__`, `*.pt`, and `*_data/`.

### 4. No HEALTHCHECK defined — LOW
**Risk:** Orchestrators cannot distinguish a hung or compromised container from
a healthy one, delaying detection.
**Fix:** Add a `HEALTHCHECK` that probes the `/health` endpoint on port 5001.

### 5. Build tools remain in the production image — MEDIUM
**Risk:** `build-essential` and `gcc` stay in the final image, enlarging the
attack surface and letting an attacker compile native exploits at runtime.
**Fix:** Use a multi-stage build — compile wheels in a builder stage, copy only
the installed packages into a slim runtime stage.

### 6. Unnecessary network/VCS tools in the image — LOW
**Risk:** `curl` and `git` are present in the runtime image. Neither is needed
to serve the app, and both are classic lateral-movement / exfiltration tools.
**Fix:** Remove `curl`/`git` from the runtime image or confine them to a
transient build stage.

## AI Pipeline Risk Assessment

These supply-chain issues map directly onto AI-specific risks:

- **Model integrity.** Because `COPY .` bakes the `receipt_cnn_clean.pt`
  checkpoint and the datasets into the image with no integrity check, a
  tampered checkpoint (e.g. one trained on the Phase 2 poisoned data) could be
  shipped unnoticed. There is no model signing or hash verification in the
  pipeline. **Recommendation:** check in a SHA256 of each released checkpoint
  and verify it at load time.
- **Dependency confusion / poisoning.** The unpinned base image and the two
  packaging-layer CVEs (`wheel`, `jaraco.context`) show the install path itself
  is attackable — a malicious wheel can execute code at build time, which is the
  classic foothold for dependency-confusion attacks. **Recommendation:** pin all
  dependencies with hashes (`pip install --require-hashes`) and pin the base
  image by digest.
- **Runtime privilege.** Root + build tools + `curl`/`git` means that a
  successful prompt-injection-driven RCE lands as root with a full toolchain for
  escalation and exfiltration. **Recommendation:** non-root user, multi-stage
  slim runtime, and drop Linux capabilities.
- **Secret exposure.** The OpenAI/Vocareum API key lives in `.env`; `COPY .`
  without `.dockerignore` risks embedding it in an image layer where it is
  recoverable even after deletion.

## Remediation Priority

| Priority | Action |
|----------|--------|
| 1 | Run the container as a non-root user and add a `.dockerignore` so secrets, `.git`, checkpoints, and datasets are never baked into the image. |
| 2 | Upgrade the two fixable HIGH Python packages (`wheel` ≥ 0.46.2, `jaraco.context` ≥ 6.1.0), pin all deps with hashes, and pin the base image by digest. |
| 3 | Move to a multi-stage build that drops build tools, `curl`, and `git` from the runtime image; add a HEALTHCHECK; rebuild on the latest patched base image on a schedule to clear the no-fix Debian/kernel findings. |
